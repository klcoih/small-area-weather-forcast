# 小区域气象预测系统平台 —— 项目文档

---

## 一、项目背景

### 1.1 问题来源

在农业生产中，气象条件对作物生长、病虫害防治和灌溉决策具有决定性影响。传统的大范围天气预报分辨率较低（通常以城市或区县为单位），难以精确反映小区域（如单个温室大棚）的实际气象状况。尤其是：

- **温室大棚**内部温湿度与户外存在显著差异（大棚保温/保湿效应）
- **精准农业**需要15分钟级的高频预测来指导通风、遮阳、灌溉等操作
- **极端天气事件**（大风、强降雨）需要提前预警，减少农业损失

### 1.2 研究区域

本项目以**云南省宣威市尚营种业基地**为研究对象，该基地同时部署了：

- **大棚温湿度传感器**：采集大棚内部温度和湿度数据
- **户外自动气象站**：采集户外温度、湿度、光照强度、风向、风速、降雨量等6项气象指标

### 1.3 技术挑战

- **多时间尺度建模**：需要在15分钟、小时、天、周等多个时间尺度上捕捉气象变化规律
- **环形数据建模**：风向是0-360°的环形变量，不能直接用常规回归方法
- **零膨胀问题**：降雨量数据存在大量零值（晴天），非零部分分布严重右偏
- **小样本 vs 大样本**：大棚数据仅约610条（约7天），而室外数据约13万条（约5年），需要差异化处理策略
- **递归多步预测**：要实现未来24小时（96步）预测，需要递归地将预测值反馈为输入

---

## 二、项目目的

### 2.1 核心目标

构建一个**15分钟级、8个气象目标的实时预测系统**，能够：

1. **实时预测**：基于最新观测数据，预测下一个15分钟的气象状态
2. **未来预测**：递归预测未来24小时（96步）的气象变化趋势
3. **可视化展示**：通过Web仪表盘直观展示预测结果和历史数据

### 2.2 预测目标

| 编号 | 目标名称 | 内部名称 | 单位 | 类型 | 说明 |
|------|----------|----------|------|------|------|
| 1 | 大棚温度 | greenhouse_temperature | °C | 连续回归 | 温室内部温度 |
| 2 | 大棚湿度 | greenhouse_humidity | % | 连续回归 | 温室内部湿度 |
| 3 | 室外温度 | outdoor_temperature | °C | 连续回归 | 户外大气温度 |
| 4 | 室外湿度 | outdoor_humidity | % | 连续回归 | 户外大气湿度 |
| 5 | 光照强度 | light_intensity | lux | 连续回归 | 太阳辐射强度 |
| 6 | 风向 | wind_direction | ° | 向量回归 | 环形数据(0-360°) |
| 7 | 风速 | wind_speed | m/s | 连续回归 | 加权回归(大风重加权) |
| 8 | 降雨量 | rainfall | mm | 两阶段 | 分类(有雨/无雨)+回归(降雨量) |

### 2.3 系统功能

- **REST API 服务**（FastAPI）：提供标准化预测接口
- **Web 仪表盘**（Chart.js）：实时数据可视化、历史趋势、预测曲线
- **数据上传**：支持 CSV/JSON 格式的传感器数据追加
- **模型管理**：支持多种模型（XGBoost、LSTM、ARIMA、Prophet、Markov）的热加载和切换

## 四、实现步骤

### 4.1 数据预处理管线

#### 4.1.1 数据加载与标准化

分别实现了大棚数据加载器（`greenhouse_data_loader.py`）和室外数据加载器（`outdoor_weather_loader.py`），各自负责：

**大棚数据加载器功能：**
- CSV/Excel 文件读取，支持中文列名自动映射
- 时间序列间隔检查（期望15分钟均匀间隔）
- 异常值检测（温度范围 -10~50°C，湿度范围 0~100%）
- 缺失值统计与报告
- 数据标准化：重命名列、添加数据源标记

**室外数据加载器功能：**
- CSV/Excel 文件读取，支持多文件批量加载
- 时间间隔检查（允许30%不均匀度容差）
- 多字段异常值检测（温度、湿度、光照、风速、风向、降雨量）
- 特殊字段处理：零膨胀降雨量、静风风向、夜间光照
- 数据质量报告生成

#### 4.1.2 时间对齐与清洗

实现 `TimeAligner` 类，将原始数据对齐到统一的15分钟网格：

```
原始数据                   对齐后
2021-04-01 12:03 ─┐      2021-04-01 12:00
2021-04-01 12:18 ─┤  →   2021-04-01 12:15
2021-04-01 12:32 ─┘      2021-04-01 12:30
```

实现 `DataCleaner` 类，支持三种异常值检测方法：
- **IQR 法**：基于四分位距（factor=1.5）
- **3σ 法**：基于标准差（factor=3.0）
- **IQR+3σ 联合法**：同时满足两个条件才标记异常

缺失值填充策略：线性插值（默认）、前向填充、零填充

#### 4.1.3 特征工程管线

特征工程是系统的核心，通过 `FeatureEngineer15min` 类实现了完整的特征构建流程：

**滞后特征（Lag Features）：**

| 类别 | 滞后步数 | 时间跨度 | 用途 |
|------|----------|----------|------|
| 短期 | lag_1, lag_2, lag_4 | 15min, 30min, 1h | 最近变化趋势 |
| 中期 | lag_96, lag_192 | 1天, 2天 | 日周期模式 |
| 长期 | lag_672 | 1周 | 周周期模式 |

**时间特征（Time Features）：**
- `hour`（0-23）：小时
- `minute`（0/15/30/45）：分钟
- `day_of_week`（0-6）：星期
- `month`（1-12）：月份
- `is_daytime`（0/1）：日间/夜间标记
- `hour_sin`、`hour_cos`：小时的正弦/余弦编码（捕获周期性）

**滚动统计特征（Rolling Features）：**
- `rolling_mean_4`（1小时均值）、`rolling_mean_16`（4小时均值）
- `rolling_std_4`（1小时标准差）

**交叉特征（Cross Features）：**
- `temp_diff`：大棚温度 - 室外温度（大棚保温效应）
- `humidity_diff`：大棚湿度 - 室外湿度（大棚保湿效应）
- `temp_humidity_interaction`：温度 × 湿度（温湿交互效应）

**特殊预处理：**
- **风向**：角度(0-360°) → sin/cos 向量分解 → `wind_sin`, `wind_cos`
- **降雨量**：二值化 → `rain_flag`（阈值 0.1mm）
- **光照强度**：夜间标记 → `is_night`（阈值 100 lux）

#### 4.1.4 大棚与室外差异化策略

由于大棚数据量极少（~610条），无法使用中长滞后特征（lag_96、lag_672），因此大棚和室外采用不同的特征配置：

| 配置项 | 室外 | 大棚 |
|--------|------|------|
| 短期滞后 | lag_1,2,4 | lag_1,2,4 |
| 中期滞后 | lag_96,192 | lag_96（仅当数据量足够时） |
| 长期滞后 | lag_672 | 不使用 |
| 滚动均值 | mean_4, mean_16 | mean_4 |
| 滚动标准差 | std_4 | std_4 |
| 交叉特征 | 全部启用 | 全部启用 |
| 特殊预处理器 | 风向/降雨/光照 | 不使用 |

### 4.2 模型训练

#### 4.2.1 数据划分

采用时间序列顺序划分（`time_series` 方法），避免数据泄露：
- 训练集：前 80%
- 验证集：中间 10%
- 测试集：后 10%

#### 4.2.2 模型选型

针对8个不同预测目标的特点，选择了4种模型类型：

| 目标 | 类型 | 推荐模型 | 原因 |
|------|------|----------|------|
| 大棚温度 | 回归 | XGBoost | 特征丰富，快速可靠 |
| 大棚湿度 | 回归 | XGBoost | 同上 |
| 室外温度 | 回归 | XGBoost | 多特征融合，滞后特征丰富 |
| 室外湿度 | 回归 | XGBoost | 同上 |
| 光照强度 | 回归 | XGBoost | 使用 is_daytime 和 hour_sin/cos 编码 |
| 风向 | 向量回归 | XGBoost | 分别训练 sin 和 cos 回归器 |
| 风速 | 回归 | XGBoost | 加权回归 |
| 降雨量 | 两阶段 | XGBoost | 分类+回归两阶段 |

#### 4.2.3 模型训练流程

```
原始数据 → 数据加载器 → 标准化数据
    → PreprocessingPipeline → 特征工程数据
    → prepare.py → 训练集/验证集/测试集
    → train.py → 模型训练 → 评估 → results.csv
    → save_models.py → 最佳模型保存为 .pkl
```

**训练脚本 (`scripts/train.py`)** 支持：
- 单模型单目标训练
- 自动化网格搜索（`--auto` 模式遍历所有模型×目标组合）
- 支持命令行参数指定模型、目标和超参数
- 结果自动追加写入 `results.csv`

**模型保存脚本 (`scripts/save_models.py`)** 功能：
- 自动选择最佳超参数组合
- 在完整训练+验证集上重新训练
- 在测试集上评估最终性能
- 保存模型元数据（特征列名、目标类型、训练时间等）
- 输出 .pkl 文件到 `models/` 目录

#### 4.2.4 特殊模型处理

**风向（向量回归）：**
```
原始角度 θ → [sin(θ), cos(θ)] → 分别训练两个回归器
预测 → [sin_pred, cos_pred] → θ_pred = arctan2(sin_pred, cos_pred) % 360
评估指标：平均绝对角度误差（考虑环形特性）
```

**降雨量（两阶段模型）：**
```
阶段1 - 分类器：预测有雨/无雨 (rain_flag, 阈值 0.1mm)
  ├── XGBClassifier
  ├── 评估: AUC, Brier Score, CSI
  └── 输出: 降雨概率

阶段2 - 回归器：仅在降雨样本上训练
  ├── XGBRegressor (log1p 变换)
  ├── 评估: MAE (rain_only)
  └── 输出: 降雨量预测

合成指标: val_composite = 0.5×cls_score + 0.5×reg_score
```

### 4.3 实时预测系统

#### 4.3.1 单步预测 (`predict_now.py`)

```
ModelLoader: 加载 .pkl 模型文件
FeatureProvider: 运行预处理管线生成最新特征
Predictor: 使用最新特征 + 模型 → 预测下一时刻
```

支持三种预测类型：
- **回归**：直接输出预测值
- **向量回归**：预测 sin/cos，反算角度
- **两阶段**：先分类（有雨/无雨），若有雨则回归降雨量

#### 4.3.2 递归多步预测 (`forecast_engine.py`)

```
递归预测算法：
  for step in 1..96:
    1. 用当前特征预测 t+step 时刻的目标值
    2. 将预测值作为"已知数据"追加到时间序列
    3. 在扩展后的数据上重新运行特征工程管线
    4. 用新特征预测 t+step+1 时刻
    5. 重复直到达到目标步数
```

关键技术点：
- 每步重新运行完整的 `FeatureEngineer15min` 管线，确保特征一致性
- 使用原始数据的最新时间戳修正预测起点，避免管线滞后特征导致的时间偏差
- 支持预测失败时回退到上一个有效值（fallback）

### 5.2 结果分析

1. **XGBoost 表现卓越**：在所有回归目标上，XGBoost 均取得了远超其他模型的表现。室外温度 R²=0.99988，室外湿度 R²=0.99988，光照强度 R²=0.99960，风速 R²=0.99822。风向角度误差仅 0.82°，非常精准。

2. **ARIMA 和 Prophet 效果不佳**：在15分钟级高频数据上，ARIMA 和 Prophet 表现较差，R² 均为负值（即预测效果不如简单取均值）。这是因为：
   - ARIMA 是单变量模型，无法利用丰富的特征工程
   - Prophet 更擅长低频数据（日/周/月），在15分钟级数据上拟合困难
   - 室外数据跨度5年，模式变化大，简单周期性模型难以捕捉

3. **LSTM 未充分训练**：LSTM 的 R² 全为 0.0（即预测值等于均值），说明 LSTM 模型未充分收敛或训练配置需要优化。大棚数据量小（~610条）可能是 LSTM 表现不佳的原因之一。

4. **降雨量预测困难**：所有模型在降雨量预测上表现不佳，CSI=0.0、AUC=0.5。这是因为：
   - 降雨是高度稀疏的事件（大量零值，降雨样本极少）
   - 当前的分类阈值和特征可能不足以有效区分降雨事件
   - 降雨量预测本质上是一个极其困难的小概率事件预测问题

5. **马尔可夫链**：accuracy=1.0 但 CSI=0.0，说明模型将所有样本都预测为"无雨"（因为无雨样本占绝大多数），没有实际预测能力。

### 5.3 最终部署模型

基于实验结果，系统最终选择 **XGBoost** 作为主力预测模型，训练并保存了以下8个模型文件：

## 七、改进方向

### 7.1 数据层面

1. **扩充大棚数据**
   - 大棚数据仅约7天（610条），严重限制了模型学习能力
   - 建议持续采集大棚温湿度数据，至少积累3个月以上
   - 可考虑增加更多传感器（如CO₂浓度、土壤湿度等）

2. **降雨量数据增强**
   - 当前降雨量预测效果极差，需要更多降雨事件样本
   - 可引入雷达回波数据、卫星云图等外部数据源
   - 考虑使用合成少数类过采样技术（SMOTE）处理类别不平衡

3. **数据质量提升**
   - 建立数据质量监控告警机制
   - 传感器校准和维护记录纳入系统

### 7.2 模型层面

1. **LSTM 模型优化**
   - 当前 LSTM 未有效收敛，需要深入调参
   - 尝试不同的序列长度（seq_length=96/192/672）
   - 调整学习率调度策略（余弦退火、ReduceLROnPlateau）
   - 增加训练轮次（epochs=100+）
   - 对大棚数据使用迁移学习（先在室外数据上预训练）

2. **降雨量模型改进**
   - 尝试使用极端梯度提升的 scale_pos_weight 参数处理不平衡
   - 引入更多降雨相关特征（湿度变化率、气压、露点温度等）
   - 考虑使用 Tweedie 回归（专门处理零膨胀数据）
   - 尝试深度学习方法（如 DeepAR、Temporal Fusion Transformer）

3. **集成学习**
   - 对多个模型进行加权集成（Stacking/Blending）
   - 对不同的预测目标使用不同的最佳模型
   - 引入模型不确定性估计（Quantile Regression）

4. **模型更新策略**
   - 实现在线学习/增量学习，随着新数据到来持续更新模型
   - 建立模型性能退化检测机制，自动触发重新训练

### 7.3 功能层面

1. **异常预警系统**
   - 基于预测结果设置阈值告警（高温预警、暴雨预警、大风预警等）
   - 支持邮件/短信/微信等多渠道通知
   - 建立预警分级机制（蓝色/黄色/橙色/红色）

2. **决策支持**
   - 基于预测结果生成农业操作建议（通风、遮阳、灌溉、施肥等）
   - 病虫害风险预测模型
   - 作物生长模型集成

3. **多站点扩展**
   - 支持多个大棚/基地的同时监控
   - 站点间的对比分析
   - 空间插值实现区域气象预测

4. **用户系统**
   - 多用户权限管理
   - 自定义仪表盘配置
   - 预测报告自动生成和导出

### 7.4 工程层面

1. **性能优化**
   - 递归预测目前每步都重新运行特征工程管线，耗时较长（96步约需1-2分钟）
   - 可优化为增量特征更新，只重新计算新追加行的特征
   - 考虑使用缓存机制避免重复计算

2. **容器化部署**
   - Docker 容器化，便于环境复现和部署
   - 使用 Docker Compose 编排多服务

3. **CI/CD**
   - 自动化测试（单元测试、集成测试）
   - 模型训练流水线自动化
   - 模型版本管理（MLflow / DVC）

4. **数据库集成**
   - 当前使用 CSV 文件存储，不适合生产环境
   - 迁移到时序数据库（InfluxDB / TimescaleDB）
   - 建立数据备份和恢复机制

### 7.5 前端优化

1. **移动端适配**
   - 响应式设计，支持手机/平板访问
   - 微信小程序版本

2. **交互增强**
   - 支持时间范围选择器（缩放/平移历史数据）
   - 预测置信区间可视化
   - 多指标联动对比图

3. **实时性提升**
   - WebSocket 实时推送最新预测结果
   - 自动刷新机制

## 八、总结

本项目成功构建了一个**小区域气象预测系统平台**，实现了对温室大棚和户外环境的15分钟级高频预测。系统采用 XGBoost 作为主力模型，结合丰富的特征工程（滞后特征、时间特征、滚动统计特征、交叉特征、特殊预处理器），在温度、湿度、光照、风速等7个回归目标上取得了优异的预测效果（R² > 0.92）。

系统提供了完整的 REST API 和 Web 仪表盘，支持实时预测、未来24小时趋势预测、历史数据查询和数据上传等功能，能够为精准农业决策提供数据支撑。

主要不足在于降雨量预测和 LSTM 模型效果不佳，需要在数据积累和模型优化方面持续改进。大棚数据量偏少也是制约模型性能的瓶颈之一。
